# Доступ к AI-сервисам: исследование

Дата проверки репозиториев: 20 ноября 2026. Рассмотрены исходники/README проектов; доступ из российской сети и аккаунты сервисов не проверялись. Местонахождение пользователя — Латвия; настройки компьютера для России автоматически не применяются.

| Проект | Что предлагает автор | Зависимость |
| --- | --- | --- |
| [GeoFree](https://github.com/Takeh1ko/GeoFree) | Перенаправление доменов AI-сервисов через записи hosts; резервная копия и восстановление | Сторонний Smart DNS / SNI-прокси |

В README перечислено предполагаемое назначение; это не независимое подтверждение работоспособности. Даже ответ HTTPS 200 от стартовой страницы не проверяет авторизацию, генерацию ответа, API и ограничения аккаунта.

## Почему одной локальной программы недостаточно

zapret изменяет вид трафика для DPI, но не переносит исходящий IP в другую страну. Smart DNS работает иначе: выбранные имена возвращают адрес сервера пересылки; соединение с целевым сервисом устанавливает этот внешний сервер. TLS может оставаться сквозным при прозрачной пересылке, но оператор маршрута всё равно становится частью инфраструктуры доверия.

В Relay реализована отдельная функция с публичным оператором dns.malw.link, 43 выбранными AI-доменами и удалением собственного блока hosts при отключении. Она выключена по умолчанию и включается отдельной кнопкой. Собственный сервер, NRPT и настройка DNS в текущей сборке не реализованы. Из коробки нельзя честно обещать бессрочный доступ ко всем нейросетям без внешних серверов.

## Фактическая проверка выбранных маршрутов

Выполнены HTTPS-запросы с принудительным адресом SNI-прокси (`curl --resolve`), без изменения системного hosts и без входа в аккаунты. Проверка TLS включена. ChatGPT ответил HTTP 200 после первого таймаута и повторной проверки; Gemini ответил HTTP 200. Claude вернул HTTP 403 с `Cf-Mitigated: challenge` (браузерная проверка Cloudflare). Это не доказывает вход, генерацию или обход геоблока из России. Публичный провайдер может менять адреса и доступность.

Важно покрывать связанные домены авторизации и API, а не только главную страницу. EuroDNS описывает такую проблему на примере Gemini. Его утверждения о совместимости браузеров и QUIC/ECH требуют отдельной проверки; README проекта не следует считать гарантией поведения каждого клиента.
