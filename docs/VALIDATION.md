# Проверки Relay 0.2.0

20 ноября 2026, Windows 11 x64.

- Release-сборка и clippy со всеми targets и `-D warnings` успешны.
- 28 unit-тестов и 2 интеграционных теста проходят. Дополнительно проверены остановка поиска на первом успешном ALT, отмена до и после проверки, занятый локальный порт без завершения его владельца и границы/сохранение настроек анимации. Добавлены тесты ALT-профилей, выбора версии GitHub, отклонения повреждённого exe и другой архитектуры, экранирования путей установщика. Замена файла и отказ при несовпадении SHA-256 проверены настоящим PowerShell/File.Replace в отдельной временной папке; запуск нового процесса и задержка в этом тесте заменены заглушками.
- Сборка 0.2.0 заменила предыдущий exe и запущена с сохранённым Telegram-подключением. Конфигурация мигрировала с general.bat на ALT 1; зимняя анимация и автообновление включены. Процесс нового окна подтверждён. Его working set в одном замере — около 22 МБ, без гарантии для других условий и без включения Telegram-worker в этот замер.
- Промежуточная сборка с подбором ALT, диагностикой, треем и ползунками запущена. Скругление кнопок в окне «Оформление» подтверждено визуально. Обнаружен белый фон ползунков; исправление отключает системную тему только этих контролов и задаёт цвет фона карточки. Замена файла с этим исправлением и проверкой обновлений только при запуске не завершена: пользователь отменил UAC, затем остановил Computer Use через Escape. Последняя сборка сохранена отдельно как Relay-new.exe; её оформление повторно через UI не проверено.
- В одном замере промежуточная оболочка занимает около 23 МБ working set, Telegram-worker — около 15 МБ, всего около 38 МБ. Это наблюдение на текущем ПК, а не гарантия пика или нагрузки при подборе ALT. Размер буферов анимации фиксирован; ползунки не создают новые кадровые буферы.
- Полный живой перебор ALT и восстановление профиля не проверялись: действует независимая служба zapret. Логика выбора и отмены проверена unit-тестом; реальные служебные операции остаются ограничением проверки.
- Служба RelayZapret реализована через SCM, с защищённой папкой и ручным запуском. Установка и запуск этой службы не выполнялись при проверке: на ПК уже работает отдельная upstream-служба zapret. Она не изменялась. Проверка обхода в российской сети по-прежнему отсутствует.
- Автоматическая проверка GitHub выполняется один раз при запуске; повторного таймера нет. Кнопка остаётся для ручной проверки. Переключатель применяется к следующему запуску.
- GitHub проверяется по опубликованным релизам, автоматическая проверка создала last-check. На GitHub пока опубликована 0.1.0; полноценная загрузка и установка будущего релиза через интерфейс ещё не проверена. Updater не является подписью издателя.

## Ранее выполненные проверки 0.1


Дата: 20 ноября 2026. Windows 11 x64, Rust 1.100.0. Сеть не является проверенной российской сетью; пользователь указал Латвию.

## Что подтверждено

- Сборка release успешна, с иконкой в Windows-ресурсах.
- `cargo clippy --locked --all-targets -- -D warnings`: без замечаний.
- 18 unit-тестов и 2 интеграционных теста Relay проходят. Дополнительно проверены совместимость старого JSON, перезапись файла настроек с сохранением секрета Telegram, сериализация плана восстановления, экранирование путей автозапуска, удаление только собственного задания и создание объектов ScheduledTasks в режиме проверки без регистрации задания. Применение задания и реальный вход в Windows во время разработки не выполнялись.
- Новый раздел «Запуск и восстановление» визуально проверен в работающем окне. Переключатели по умолчанию выключены; в неповышенном процессе настройка автозапуска недоступна и рядом показана кнопка перезапуска с правами администратора. При проверке сами опции не включались.
- Трей: после нажатия крестика Relay исчез из списка видимых окон, но исходный процесс остался жив. Повторный запуск exe вернул то же окно с тем же HWND. Регистрация значка прошла (при неудачной регистрации ветка скрытия не используется). Контекстное меню значка, полный выход и перезапуск Проводника визуально не проверены: дальнейший Computer Use остановлен пользователем клавишей Escape. Код этих ветвей проходит clippy и release-сборку.
- Проверки архива, всех стратегий, путей, секрета, ограниченного журнала и AI hosts проходят. Проверено атомарное применение/отмена на отдельном тестовом файле, сохранение чужих правок, отказ при конфликтах, повреждённых маркерах и непубличных адресах.
- 2 интеграционных теста проходят: Rust-библиотека слушает только loopback и освобождает порт после остановки; настоящий worker из того же exe завершается при закрытии Windows Job Object.
- Сквозная проверка `--tg-worker --check-listener` завершилась кодом 0. Локальный listener выполнил MTProto probe через WebSocket до DC2 (`149.154.167.220`) и получил ожидаемый ответ. Результат: `all checks passed`, около 437 мс. Учётная запись Telegram и сообщения пользователя не использовались.
- Выборочные upstream integration suites: config 48, crypto 12, FakeTLS 12, server 7, splitter 8 — проходят. Эти upstream tests запускались на закреплённом исходном коммите с его собственным Cargo.lock.
- При начальном запуске нативного GUI зафиксировано около 13 МБ working set, 1,9 МБ private bytes, без активных движков. Более ранняя egui/OpenGL-версия показала около 170 МБ working set и заменена на Win32/GDI. Сравнение относится к одному ПК, режиму простоя и одному способу измерения.
- Финальная сборка с AI-модулем: 6,53 MiB. После запуска рабочего окна наблюдалось 16–23 МБ working set; движки и AI-маршрут выключены. Все исполняемые компоненты входят в exe; загрузки во время запуска нет.

## Что не подтверждено

- Обход на конкретных провайдерах РФ, воспроизведение YouTube, голос Discord и длительная работа под нагрузкой.
- Ограничения аккаунтов и регионов ChatGPT, Claude и Gemini. AI hosts-маршрут реализован, но на системный hosts во время разработки не применялся. Проверка прямого HTTPS через адреса провайдера с сохранением TLS дала ChatGPT HTTP 200 (первый запрос — таймаут, повторный — 200), Gemini HTTP 200, Claude HTTP 403 / Cloudflare challenge. Вход и генерация не проверялись.
- Первую визуальную проверку остановили Escape. После отдельного запроса на исправление визуальной части главный экран повторно проверен: фон углов owner-drawn кнопок совпадает с родительскими панелями, ICO загружается в нативных размерах 16/32/48/64 вместо растягивания первого кадра 16 px; заголовок тёмный. Проверка всех остальных разделов через UI не завершена.
- Экономия RAM на других GPU/версиях Windows и при загрузке медиа.

## Неуспешные upstream проверки

Полный unit-набор стороннего порта дал 75 успешных тестов и 1 неуспешный: `proxy::tests::a_pinned_ladder_re_probes_a_cooled_dc_ip_when_every_rung_fails`. Повторный отдельный запуск также не прошёл: тест ожидает невозможность соединения, но получает upstream. Причина не установлена; нельзя утверждать, что это только проблема окружения. Relay не использует пользовательские pinned ladders, но это всё равно ограничение уверенности в исходной библиотеке.

В upstream `outbound` 25 тестов прошли, 3 не прошли: IPv6 NO_PROXY с ошибкой Windows 10013 и два теста обхода прокси по суффиксу домена с таймаутом TCP. Эти ветви внешнего proxy/NO_PROXY Relay отключает параметром `--no-outbound-proxy`. Причины сетевых ошибок на этом ПК полностью не установлены.

Таким образом, «все тесты всего upstream прошли» не заявляется. Версия остаётся экспериментальной, несмотря на успешную реальную MTProto/WebSocket-проверку.

## Границы проверки целостности

SHA-256 сверяет встроенный архив и неизменяемые файлы перед запуском. Это не подпись издателя и не независимый аудит upstream. Приложение не подписано сертификатом разработчика.
